1. Setup

Virtual environment

Homebrew Python blocks pip install system-wide (PEP 668: externally-managed-environment), so a venv is required.

mkdir mlx-tuning && cd mlx-tuning
python3 -m venv my_env
source my_env/bin/activate
pip install mlx-lm
pip install --upgrade pip

This installed mlx 0.32.3, mlx-lm 0.32.0, transformers 5.19 and huggingface-hub 1.33.

Hugging Face login (for the gated Gemma model)

The first run failed with 401 Unauthorized / GatedRepoError because Gemma requires accepting Google's license and authenticating. huggingface-cli is deprecated, so the new hf command is used.

hf auth login        # paste a token
mlx_lm.generate --model google/gemma-3-270m-it --prompt "Write a short haiku about artificial intelligence"
The token is stored in ~/.cache/huggingface/token. Keep it private. Llama 3.2 from mlx-community needs no login.

5. Training: Llama 3.2 3B (4-bit)

This is a bigger model, so memory-saving options were used: batch size 1 and only 8 LoRA layers. 4-bit base weights plus LoRA is effectively QLoRA.

  --model mlx-community/Llama-3.2-3B-Instruct-4bit \
  --train \
  --data ./data \

6. Fusing the adapter into the model

An adapter is a small add-on file loaded on top of the base model. Fusing merges it into the weights so you get a standalone model folder.

mlx_lm.fuse \
  --model mlx-community/Llama-3.2-3B-Instruct-4bit \
  --adapter-path adapters_llama \
  --save-path fused_llama

Fusion results, two runs

fused_llama (4-bit)
"I couldn't find any information on a company called 'Seeroo IT Solutions'…"

The fused 4-bit model lost the learned fact. Merging LoRA deltas into already-quantized weights and re-quantizing rounds away a very small update (lr 1e-5, 100 iters). The first test also hit a 404 on a later run, because the path was resolved as a Hugging Face repo id.

fused_llama_8bit
"Seeroo IT Solutions has its main corporate headquarters at Santhigiri Campus, NAD Road, Kalamassery, Kochi, Kerala, India. They also have an office in the Vismaya Building at Infopark Kochi."

Dequantized fuse then 8-bit re-quantize, so the fact survives. Peak memory is 3.5 GB and generation is slower (17 tok/s vs 28 tok/s).

How fused_llama_8bit was made

Recovered from an earlier Claude Code session. The fix was a two-step process: fuse with --dequantize to get full-precision weights that keep the tiny LoRA update, then re-quantize to 8-bit.

mlx_lm.fuse \
  --model mlx-community/Llama-3.2-3B-Instruct-4bit \
  --adapter-path adapters_llama \
  --save-path fused_llama \
  --dequantize

mlx_lm.convert \
  --hf-path fused_llama \
  --mlx-path fused_llama_8bit \
  -q --q-bits 8 --q-group-size 64

A 4-bit re-quantize (fused_llama_4bit) was also tried and, along with the intermediate fused_llama, deleted afterwards to save disk space. fused_llama_8bit/config.json confirms 8 bits, group size 64.

For a local, relative path, run mlx_lm.generate --model ./fused_llama_8bit …. Without ./ it still worked here because the folder exists, but a missing folder falls through to a Hugging Face lookup and the 404 above.

7. Running Llama 3.2 3B with llama.cpp

llama.cpp is an inference engine only; it can't train. So it runs the base model as-is, or a fine-tuned model after converting it to GGUF.

llama-cli -hf bartowski/Llama-3.2-3B-Instruct-GGUF:Q4_K_M

This GGUF is the un-fine-tuned base model, so it behaves like the "before training" Llama answer, not the Seeroo one.

Fine-tuned model in llama.cpp (done)

The adapter was fused with --dequantize into full-precision fused_llama (6 GB), converted to GGUF, then quantized.

git clone --depth 1 https://github.com/ggml-org/llama.cpp ~/llama.cpp-src
python3 -m venv ~/llama.cpp-src/venv          # separate venv, see warning below
~/llama.cpp-src/venv/bin/pip install -r ~/llama.cpp-src/requirements/requirements-convert_hf_to_gguf.txt
~/llama.cpp-src/venv/bin/pip install "transformers>=5.7.0"

~/llama.cpp-src/venv/bin/python ~/llama.cpp-src/convert_hf_to_gguf.py fused_llama \
  --outfile ~/llama-models/llama-3.2-3b-finetuned-f16.gguf --outtype f16

llama-quantize ~/llama-models/llama-3.2-3b-finetuned-f16.gguf ~/llama-models/llama-3.2-3b-finetuned-Q4_K_M.gguf Q4_K_M
llama-quantize ~/llama-models/llama-3.2-3b-finetuned-f16.gguf ~/llama-models/llama-3.2-3b-finetuned-Q8_0.gguf Q8_0

llama-cli -m ~/llama-models/llama-3.2-3b-finetuned-Q8_0.gguf -p "where is seeroo it solutions located" -st
FileSizeSeeroo answer
finetuned-f16.gguf6.0 GBNot tested (intermediate)
finetuned-Q8_0.gguf3.2 GBCorrect, matches training text exactly (~12 tok/s)
finetuned-Q4_K_M.gguf1.9 GBFact kept, but one run added an invented UAE office address (~25 tok/s)
Pitfall: the converter's requirements file downgrades transformers to 4.x, which breaks mlx-lm in my_env. Use a separate venv as above. Also, llama-cli needs -st (single turn) to apply the chat template and exit. Without it, piping output gave nothing.
Q4_K_M did not wipe the fine-tune, unlike the MLX 4-bit fuse, but it is less faithful. Use Q8_0 when exactness matters.

Extras built along the way

RAG instead of fine-tuning. rag_query_web.py "where is seeroo it solutions located" retrieves from an indexed source and answered with the same address, with no training. Files: rag_index.py, rag_chunks.json, rag_embeddings.npy.

Document tools using the base Llama 3B. summarize.py file.pdf [--max-tokens N] chunks and summarizes a PDF. ask_doc.py file.pdf is an interactive Q&A over a PDF (note the underscore; askdoc.py doesn't exist). It was tried on a banker's letter and on resumes. It answered extractive questions well ("what is his email") but failed on inference questions ("who am I talking to", "years studied"), which is typical of small models.

Takeaways

  • LoRA with 100 iterations on 3 repeated examples is enough to inject a specific fact into both models.
  • Fine-tuning is good for style and facts you control. RAG is safer for facts that change or need citations.
  • Merge adapters into higher-precision weights, or keep them separate, when the base model is 4-bit.
  • Add more varied phrasings of each question to get reliable recall beyond the exact training prompts.
